Amendment window enforcement
Server-side enforcement of the amendment window. Once an order reaches the locked state defined by clinic_config.amendment_window, no amendment endpoints will mutate the order — the API rejects with 403. Enforcement is evaluated server-side regardless of what the client sends, including UI state. DEC-01 locked: both VSC and FeelTru run on pre_dispensed (lock at Primed dispensing event). pre_approval retained as a config option for future third-party clinics without Primed API connection.

The rule: under pre_dispensed (DEC-01 locked, applies to both VSC and FeelTru), amendments are permitted while order.status ∈ ('clinical-check', 'intervention', 'approved', 'in-dispensing'). Once Primed dispatches the order, the amendment window closes. Cancellations after dispatch require a Ryft refund flow — that's a separate code path with its own audit trail, not an "amendment". For dose-increase and medication-switch amendments, the order moves back to a held state pending prescriber decision; the dispatch is paused until decision.

Server middleware — single source of truth
requireOrderStatus middleware
Express-style pseudocode · same shape works for any framework
// All four amendment endpoints mount this guard before their handler.
// Guard runs after auth, before any DB write.

function requireOrderStatus(allowed) {
  return async (req, res, next) => {
    const order = await db.orders.findOne({
      id: req.params.id,
      workspace_id: req.auth.workspace_id   // tenant isolation
    });

    if (!order) return res.status(404).json({ error: 'order_not_found' });

    if (!allowed.includes(order.status)) {
      // BLD-5.3 enforcement — log + reject
      await auditLog.write({
        type: 'amendment_blocked',
        order_id: order.id,
        attempted_by: req.auth.user_id,
        endpoint: req.method + ' ' + req.route.path,
        order_status: order.status,
        allowed_states: allowed,
        request_payload: redactPII(req.body),
        timestamp: new Date().toISOString()
      });
      return res.status(403).json({
        error: 'amendment_window_closed',
        order_status: order.status,
        message: 'Order has been dispatched and can no longer be amended.',
        next_action: 'contact_primed_or_use_refund_endpoint'
      });
    }

    req.order = order;
    next();
  };
}

// Mount on each amendment route:
router.patch('/orders/:id/dose',        requireAuth, requireOrderStatus(['clinical-check','intervention','approved','in-dispensing']), handler);
router.patch('/orders/:id/shipping-address', requireAuth, requireOrderStatus(['clinical-check','intervention','approved','in-dispensing']), handler);
router.patch('/orders/:id/items',       requireAuth, requireOrderStatus(['clinical-check','intervention','approved','in-dispensing']), handler);
router.delete('/orders/:id',             requireAuth, requireOrderStatus(['clinical-check','intervention','approved','in-dispensing']), handler);

Implementation reference for Yohan
(1) The middleware is the only place the rule lives — no per-handler duplication. (2) Tenant isolation by workspace_id happens in the same DB query, before status check — a 404 (not found) is returned for cross-tenant access attempts to avoid leaking order existence. (3) The audit_log write happens before the 403 response is sent — fire-and-forget would lose evidence. Use a transactional write or a queue with at-least-once delivery. (4) The list of allowed states comes from clinic_config.amendment_window.allowed_states — both VSC and FeelTru run pre_dispensed (DEC-01 locked, May 2026). The pre_approval mode is retained as a config option for future third-party clinics without a connected pharmacy API. (5) All six fixtures must pass in CI before BLD-5.3 is marked done.
