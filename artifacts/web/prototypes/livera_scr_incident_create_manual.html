Manual incident creation
Incidents reach Livera through four origins. Three of them — Intercom webhook, in-app patient report, and system-generated severe SE — are automatic. The fourth, manual, is what staff use when a patient reports something via phone, SMS, email, in-person, or any other channel outside Intercom. The form below captures the contact channel so that the audit trail is honest about how the report arrived.

incident entity · schema update
📦 incident_origin enum (extension to BLD-8.1)
For Yohan · two new fields for manual-origin incidents
incident_origin
enum: clinical | manual | patient_app | intercom | system · NOT NULL · default clinical · indexed
contact_channel
enum: phone | sms | email | in_person | post | other · nullable · only set when origin=manual · captures how the patient actually contacted us
contact_reference
String · nullable · for the "external" contact identifier — phone number called from, email subject, postal tracking ID, etc · for traceability when the patient calls back
Validation rule: if incident_origin = 'manual' then contact_channel is REQUIRED. Conversely, if incident_origin = 'intercom' then intercom_conversation_id is REQUIRED. Enforced server-side regardless of client payload.

Save handler · what happens on submit
For Yohan: on submit, the save handler does the following sequentially —
  1. Validate: contact_channel required when origin=manual; if channel=other, sub-field "specify channel" required.
  2. Resolve patient by ID; verify same workspace_id (tenant isolation).
  3. Write incident: incident_origin = 'manual' · contact_channel set · contact_reference set if provided · created_by_user_id = staff user · created_by_system = NULL (this is staff-initiated, not system).
  4. Write the "Action taken on call" text as the first entry in the incident's activity log (type=staff_note).
  5. If linked_order is set, transition order to intervention only when severity=severe; otherwise leave the order untouched (incident sits alongside).
  6. Notify prescriber per follow-up SLA: severe → page on-call + Monday board write-through · moderate 24h → email digest + Firebase push · mild → log only.
  7. Write AUD-04 audit event with the full payload + staff user ID.
  8. Redirect to the new incident's detail page.
Note: manual incidents do not have an Intercom conversation lock (BLD-8.4 only applies to origin = 'intercom'). They follow standard incident lifecycle: open → on hold ↔ open → resolved → closed.
