==== FIX 5 (C1): Wire lib/permissions.ts with a real role matrix ====

Currently lib/permissions.ts always returns true and is not called from anywhere. Implement the role matrix from replit.md and call can() from the right places.

Role matrix to implement:

- Owner: can everything (returns true for all actions)
- RM: can everything PLUS governance surfaces (incidents, complaints, audits)
- Prescriber: 
  * CAN: read patients, read orders, decide orders, read schedule, read incidents, read complaints, read GP letters
  * CANNOT: edit settings, marketing, billing
- Coach:
  * CAN: read own bookings, read own patient roster, write coaching_log
  * CANNOT: access any clinical surfaces, settings, prescribing data
  * Coach role only exists on clinics where coaching_enabled=true
- Admin:
  * CAN: access welcome calls, read basic patient demographics (name, phone, email, GP), read order status (without clinical details)
  * CANNOT: make clinical decisions, see prescribing data, edit settings

Implement can() with this signature:
can(user: User, action: string, resource: string, context?: { clinic?: Clinic, ownerId?: string }): boolean

Standard action verbs: "read", "write", "decide", "approve", "reject"
Standard resources: "patients", "orders", "incidents", "complaints", "gp_letters", "settings", "schedule", "coaching_log"

Where to call can() (start with these — more can be added later):
1. Sidebar.tsx: hide nav links the user can't access. e.g. don't show "Settings" link unless can(user, "read", "settings"). Don't show "Schedule" link if not can(user, "read", "schedule"). Don't show "Coaching log" surfaces unless coaching_enabled AND can(user, "write", "coaching_log").
2. OrderDetailClient.tsx: gate the Approve/Decline/Query buttons behind can(user, "decide", "orders"). The Owner (currently hardcoded) will still see them; future Prescriber roles will too; Admin and Coach roles won't.
3. PatientQuickActions.tsx: gate the action buttons behind can() checks.

The hardcoded user is currently Owner, so visually nothing should change for you — but the infrastructure now exists for role-gating in future mini-waves (Mini-wave 4 needs this for the Coach-only surfaces).
