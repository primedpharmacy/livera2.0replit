ℹ
How matching works gov.uk publishes alert text containing medicine names (active ingredient, brand, or both). Matcher extracts these tokens from the alert title and body, then checks against the per-clinic drug watchlist. A match creates an Intercom conversation in this clinic's workspace tagged mhra_alert; routing then runs through the standard tag-action rule on the Tag actions screen. No match = silent skip with audit log entry.
💊
Pre-populated from clinic product catalogue On clinic onboarding, the watchlist is auto-seeded from the medicines configured in clinic_config.products. Add or remove entries here to refine. Changes audit-logged to AUD-04. Removing a watchlisted medicine does not retroactively delete past alerts — only future polls are affected.

Routing by alert classification

MHRA classification taxonomy
ClassificationDescriptionActions triggeredActive
Class 1 recall Action now · life-threatening or serious health risk · immediate quarantine of affected stock Create incident Task to RM (4h SLA) Notify all recipients AUD-04
Class 2 recall Action within 48h · significant risk · stop using affected stock pending review Create incident Task to RM (24h SLA) Notify all recipients AUD-04
Class 3 recall Action within 5 days · low risk · advisory recall, return existing stock at convenience Task to RM (5d SLA) Notify all recipients AUD-04

MHRA gov.uk drug-device-alerts integration · BLD-INT-MHRA-01 · DEC-39 · daily-poll integration with auto-routing through Intercom tag-action rules. Per-clinic drug watchlist (auto-seeded from clinic_config.products, manually editable). Severity-based routing (Class 1–4 + DSU + FSN) with enforced minimums (DEC-36 protection — cannot disable Class 1/2 incident creation). Recipients role-based with CQC Reg 17 acknowledgement evidence trail. Visible to Owner, RM. Configuration changes audit-logged to AUD-04. Companion BLDs: BLD-INT-MHRA-02 (tag-action rule) · BLD-INT-MHRA-03 (Owner Dashboard rollup card).
