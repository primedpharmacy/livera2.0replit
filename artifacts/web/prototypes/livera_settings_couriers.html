Where the courier logic lives Primed (GPhC 1039469) operates the OBA/business accounts, generates shipping labels, files manifests, and decides which courier handles which package — including Schedule 4 controlled-drug routing rules under MHRA POM-CD distribution requirements. Livera receives primed_dispatch_event webhooks for each tracking update and maps them onto the 5 patient-facing order states from spec §14: dispatched, in_transit, out_for_delivery, delivered, exception. Settings on this page are configurable in Primed, not Livera.

Why a single webhook for all 3 couriers: Primed normalises courier-specific event payloads (Royal Mail OBA, DX webhook, DPD push API) into a single primed_dispatch_event shape before forwarding. Livera never speaks to the couriers directly — the abstraction lives in Primed. This means adding a 4th courier in future requires zero Livera changes.

Courier visibility · BLD-INT-COURIER-01 (spec §14 / DEC-14). Read-only mirror of Primed's dispatch feed. Livera does not configure couriers, hold OBA accounts, generate labels, file manifests, or apply CD-routing rules — Primed (GPhC 1039469) owns all of that. Livera receives primed_dispatch_event webhooks and maps them to the 5 patient-facing states from spec §14. To change which courier handles a dispatch type, edit the rule in Primed; the new routing flows through to Livera automatically. Visible to Owner, RM, and Admin · all roles see this read-only.
