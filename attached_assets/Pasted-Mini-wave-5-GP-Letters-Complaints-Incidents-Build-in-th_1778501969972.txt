==== MOCKED MONDAY SOURCE-OF-TRUTH PATTERN ====

DEC-37 (Complaints) and DEC-29 (Incidents) make Monday boards the system of record. Livera mirrors. For V1 we're mocking that contract — but the mock must MODEL the contract correctly so the real swap is mechanical later.

Implement these primitives in lib/api/mock.ts:

1. A simulated Monday store:
   const MOCK_MONDAY_BOARDS: Record<string, MondayBoardState> = {
     "18402056019": { items: [...], etag: "v1" },     // VSC incidents (per DEC-29 anomaly)
     "18402056019": { ... },                           // FeelTru incidents — same board (DEC-29 anomaly)
     "18409111860": { items: [...], etag: "v1" },     // VSC complaints (DEC-37)
     "18402056040": { items: [...], etag: "v1" },     // FeelTru complaints (DEC-37)
   };
   Note the DEC-29 anomaly — VSC and FeelTru BOTH write incidents to board 18402056019 in the FeelTru workspace. Model it as-is. Add a // TODO (DEC-29 anomaly: VSC incidents currently land on FeelTru workspace board) comment.

2. Wrap reads via mondayRead(boardId) — returns the current board state. Add 150-300ms delay to simulate network. Log [MONDAY READ] with boardId + item count.

3. Wrap writes via mondayWrite(boardId, op: "create" | "update", payload). Returns updated board state. Logs [MONDAY WRITE]. Updates the etag.

4. Sync layer for Livera mirror: every Livera-side fetch (listComplaints, listIncidents, getComplaint, getIncident) reads from the Monday mock first, then transforms into the Livera entity shape. Every Livera-side mutation (acknowledgeComplaint, resolveComplaint, escalateIncident, etc.) writes to Monday first, then updates the local mirror.

5. Sync status field on each entity: sync_status: "in_sync" | "out_of_sync" | "error" — initially "in_sync". For a couple of seed records, set "out_of_sync" so the UI can show the divergence state and we can demo the recovery flow.

6. [AUDIT] logs on every Monday write — same pattern as decideOrder. Critical because Monday writes are safety-relevant per DEC-36.

==== ARCHITECTURAL DISCIPLINE ====

Apply everything we learned in Mini-waves 1-4. Specifically:

- Workspace isolation: every read+write scoped to clinic_id, Suspense key={clinic_id} on every page
- Tokens only — no hex codes in components
- Clinical thresholds via clinic.config (SLA values, incident triage text, consent gates)
- 3-layer safety chain on every mutation: surface gate, data guard, [AUDIT] log
- Provider-agnostic: Monday board IDs come from clinic.config.monday_board_ids, never hardcoded in components
- Use shared components (StatusBadge, LoadingState, EmptyState, ErrorState, PageHeader, Breadcrumb)
- Server components for pages, client components only when interactive
