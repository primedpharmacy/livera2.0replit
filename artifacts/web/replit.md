Livera — Replit Agent context You are helping build the Livera admin platform — a white-label clinical SaaS frontend for UK private healthcare clinics. Frontend only. The backend is being built separately by the Certus Tech Team; this Replit project consumes a mocked API for now and will swap to the real REST API later. Stack Next.js 14 (App Router) + TypeScript (strict mode) Tailwind CSS + shadcn/ui Lucide icons Mock API layer at lib/api/mock.ts — every API call goes through here, never directly to fetch No authentication wired yet — assume a hardcoded currentUser and currentClinic from lib/context.ts until auth is added in Wave 1 follow-up What Livera is in one paragraph Livera is the operating system underneath multiple regulated clinic brands. Two clinics use it today: VSC (Virtual Slimming Clinic, mixed-gender, GLP-1 weight management) and FeelTru (women-only, CQC-registered, perimenopause focus). Both run on identical platform infrastructure with one config flag ( coaching_enabled ). The platform handles patients, orders, clinical check, prescribing, prescription fulfilment via Primed Pharmacy, consultations, incidents, complaints, GP letters, and audits. Workspace isolation between clinics is absolute — it's a UK GDPR control, not a UX feature. These are the design source of truth. Every screen you build must match its prototype counterpart. If you need to understand a screen, read the prototype HTML first . It contains the canonical structure, design tokens, colour use, sidebar IA, and behaviour. Five architectural rules — non-negotiable Workspace isolation is absolute. Every API call, every list, every detail page is scoped to clinic_id . The mock API enforces this — never bypass it. In production, this becomes Postgres row-level security. Provider-agnostic transport. Couriers via Primed, complaints via Monday, scheduling via Calendly, video via Google Meet, alerts via gov.uk → Intercom. The frontend calls a provider field on the relevant entity; the backend handles the transport. Don't hardcode provider names. All clinical logic is backend-configurable per clinic. Questionnaires, dose escalation thresholds, treatment-gap rules, SLA values, consent text, day-N nudges. Frontend reads clinic.config.* and renders accordingly. Never hardcode a threshold. 3-layer safety chain (DEC-36). Safety-critical actions (clinical decisions, prescription cancellation, GP letter sending, dose escalation) have three independent enforcement layers: surface (UI prevents), data (backend rejects), audit (every attempt logged). When you build a safety-critical surface, walk through all three layers. Mobile vs admin brand separation. The admin platform uses indigo #6366f1 + system font. The patient mobile app uses lilac #9697E8 + Poppins. Never mix. If you see lilac in a Replit-built admin screen, that's a bug. Never scatter role logic across components. See REPLIT_FRONTEND_GUIDE.md for the pattern. What NOT to do Don't invent API endpoints. If you need data and the mock doesn't have it, add to lib/api/mock.ts first , then call from the component. The mock IS the API contract — Yohan's backend will be built to match it. Don't drift from the canonical shell. If a prototype HTML has a sidebar with 4 sections, the Next.js port has a sidebar with 4 sections. Same labels, same order, same badges. Don't introduce new dependencies without checking. Stack is fixed: Next.js, TypeScript, Tailwind, shadcn/ui, Lucide. Swap requests need explicit approval. Don't bypass lib/permissions.ts for &quot;just this one component.&quot; Don't use lilac/orange colours in admin surfaces. Don't hardcode patient names other than Sarah Cookland. Don't write code that would let one workspace see another workspace's data — even in mocks. When prompted to build a screen Default workflow: Read the corresponding prototype HTML in /prototypes/ Identify what data the screen needs from the API Check if the mock API has it; add it if not Build the Next.js component, preserving the prototype's structure Use shadcn/ui primitives where they fit; bespoke components otherwise Wire to mock API; show loading state; show empty state; show error state Confirm role-based visibility via lib/permissions.ts Test workspace switching — switching workspace should reload all data If unsure about a design choice, err toward what the prototype shows .
