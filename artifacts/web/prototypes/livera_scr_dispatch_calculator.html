Dispatch date calculator
Calculates the next valid Primed dispatch date when an order is approved. Combines the four scenario rules below with the workspace holiday calendar to produce a single dispatch date that's surfaced to the patient at order confirmation and on the order detail page.
1
Same-day cutoff — orders approved before 14:00 dispatch the same working day
2
After cutoff — orders approved at or after 14:00 roll to the next working day
3
Weekend — orders approved Sat/Sun dispatch the next Monday (or first working day after)
4
Bank holiday — UK holidays from the calendar are skipped; dispatch rolls to next working day

Algorithm — for Yohan
Pseudocode for the dispatch date calculation function
1
Input — approved_at (ISO 8601 datetime, UTC), clinic_config.dispatch.cutoff (e.g. "14:00"), clinic_config.holiday_calendar.dates (array of YYYY-MM-DD strings).
2
Convert approved_at to clinic's timezone (default Europe/London). Extract candidate_date = approved date.
3
Cutoff check — if approved_time >= cutoff, advance candidate_date by 1 day (still calendar-day at this point).
4
Working day walk — while candidate_date is not a working day, advance by 1 day. A working day is: !isWeekend AND !holidayCalendar.includes(date). Loop until both conditions pass.
5
Output — return candidate_date as the dispatch date. Also surface the explanation (e.g. "rolled forward 3 days through weekend + bank holiday") for the patient-facing communication and the activity log.
6
Side effects on Approve — write timeline event dispatch_date_calculated with structured evidence: {approved_at, cutoff, holidays_skipped[], weekend_days_skipped, dispatch_date, explanation}. Trigger Omnisend dispatch confirmation with {{dispatch_date}} rendered to the patient. Update the order's estimated_dispatch_date field.
Where this calculator runs
The calculator is invoked at three points: (1) on prescriber Approve action — calculates dispatch_date and writes it to the order; (2) on the patient-facing order confirmation screen — surfaces "Estimated dispatch: {{dispatch_date}}"; (3) in the Omnisend dispatch confirmation email. The same function should be used in all three places to guarantee consistency. Holiday list is fetched fresh from clinic_config.holiday_calendar.dates each call (no caching at the function level — admin edits to BLD-3.7 take effect immediately on next approval).
